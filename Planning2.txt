Tahap Perencanaan
Fase 1: Preparasi Ekosistem & Keamanan
Melakukan pendaftaran akun pada Groq Console untuk mendapatkan akses ke model Llama 3.
Melakukan generate API Key sebagai kredensial keamanan untuk autentikasi request.
Inisialisasi proyek menggunakan framework Next.js sebagai basis aplikasi web.
Fase 2: Instalasi & Konfigurasi SDK
Menginstal library inti ai (Vercel AI SDK) dan @ai-sdk/openai untuk menjembatani aplikasi dengan Groq.
Mengatur variabel lingkungan (environment variables) di .env.local untuk menyimpan API Key secara aman.
Fase 3: Konstruksi API Route
Membangun endpoint API (Backend) yang akan menangani lalu lintas pesan antara pengguna dan AI.
Konfigurasi klien SDK agar terhubung langsung ke gateway Groq di https://api.groq.com/openai/v1.

Fase 4: Arsitektur Komponen Frontend
Merancang komponen antarmuka chat, termasuk area riwayat pesan dan kolom input teks.
Mengintegrasikan hook useChat untuk mengelola state percakapan secara otomatis di sisi klien.
Fase 5: Implementasi Real-time Streaming
Menghubungkan UI dengan API Backend untuk mengaktifkan fitur pengiriman pesan.
Melakukan pengujian intensif pada fitur streaming untuk memastikan teks muncul secara mengalir tanpa hambatan.
Fase 6: Finalisasi Visual & Responsivitas
Penerapan framework CSS (seperti Tailwind) untuk merapikan estetika gelembung chat dan tata letak.
Optimasi tampilan agar adaptif dan nyaman digunakan baik melalui perangkat desktop maupun mobile.


🗓️ Timeline Pengerjaan Minggu Ke-5 — Setup Gemini API & Dasar Embedding

Membuat akun/project pada Google AI Studio (Gemini API) dan memperoleh API Key.
Mempelajari dokumentasi resmi Gemini API untuk memahami cara penggunaan model Text Embedding (seperti text-embedding-004).
Melakukan pengujian awal dengan mengirim teks sederhana dan menerima hasil representasi vektor embedding dari Gemini.
Mengintegrasikan API Gemini ke dalam aplikasi Next.js melalui rute API menggunakan `@google/generative-ai`.
Mengatur environment variable untuk menyimpan API Key Gemini secara aman pada `.env.local`.
Menghubungkan aplikasi dengan Supabase serta memastikan ekstensi vector (pgvector) aktif.
Membuat tabel `documents` yang berisi kolom id, content, dan nilai embedding vektor numeriknya.
Melakukan commit dan push pembaruan awal ke repositori Git.

🗓️ Timeline Pengerjaan Minggu Ke-6 — Data Processing & Indexing

Menentukan sumber data yang akan digunakan sebagai knowledge base (dokumen teks, artikel, atau materi pembelajaran).
Membuat proses chunking untuk membagi dokumen menjadi potongan (chunk) kecil agar optimal diserap dalam embedding.
Menentukan ukuran chunk ideal (sekitar 200–500 token) melalui pengujian.
Mengintegrasikan model Gemini Embedding ke dalam pipeline indexing data.
Menyimpan hasil array embedding beserta konten teks tersebut langsung ke dalam database pgvector Supabase.
Melakukan pengujian pemanggilan database untuk memastikan data terindeks dan siap digunakan.
Melakukan optimasi awal terhadap struktur data dan penyimpanan embedding.
Melakukan commit dan push pembaruan kode ke repositori Git.

🗓️ Timeline Pengerjaan Minggu Ke-7 — Integrasi RAG ke Backend

Memodifikasi API route (seperti `/api/chat`) pada Next.js untuk merangkai arsitektur Retrieval-Augmented Generation (RAG).
Menambahkan fungsi menerjemahkan input pertanyaan (prompt pengguna) ke format embedding juga menggunakan model Gemini.
Mengimplementasikan vector similarity search (misal cosine similarity) pada Supabase untuk memanggil dokumen yang mirip dengan pertanyaan.
Menentukan jumlah skor/kedekatan dokumen (top-k) yang ditarik sebagai *Context*.
Menggabungkan data retrieval menjadi super-prompt yang diumpankan ke LLM (Groq) sebagai otak penjawabnya.
Melakukan penyesuaian instruksi (*system prompt*) agar model menjawab patuh bersandar pada *Context* tersebut.
Melakukan pengujian interaktif untuk memastikan jawaban final bebas dari Halusinasi.
Melakukan commit dan push pembaruan kode ke repositori Git.

🗓️ Timeline Pengerjaan Minggu Ke-8 — Optimasi, Evaluasi & Penyempurnaan

Melakukan pengujian tangguh terhadap sistem RAG dengan berbagai kombinasi pertanyaan ambigu.
Mengoptimalkan parameter retrieval seperti batasan threshold skor agar hasil makin relevan.
Melakukan evaluasi strategi chunking (overlapping chunk) dan memperbaikinya jika potongan terlalu kaku.
Melakukan optimasi indeks pada Supabase (HNSW atau IVFFlat) jika data dokumen sudah masif.
Menambahkan fitur referensi agar bot bisa menampilkan sumber kutipan dokumen asli.
Membersihkan proses integrasi agar history interaksi chat tidak membebankan RAG saat pengiriman prompt.
Memperbarui dokumentasi proyek (README.md) dengan penjelasan tata cara implementasi RAG berbasis kombinasi maut Groq dan Gemini API.
Melakukan commit final dan push ke repositori Git.
